# เปิดบัญชีผู้ใช้และความก้าวหน้าบนคลาวด์

หน้าเว็บและบทเรียนใช้ได้ทันทีบน GitHub Pages แม้ยังไม่ตั้งค่า Supabase
ระบบบัญชีแสดงสถานะว่าไม่เปิดใช้งานจนกว่าจะมีการเชื่อมต่อจริง ไม่มีการจำลองล็อกอินในเครื่อง

## 1. สร้างโปรเจกต์

1. สร้างบัญชีที่ https://supabase.com และเลือก New project
2. เลือก region ใกล้ผู้เรียน ตั้งรหัสผ่านฐานข้อมูล และรอโปรเจกต์พร้อมใช้งาน
3. เปิด SQL Editor แล้วรันไฟล์ [schema.sql](./schema.sql) ทั้งไฟล์
4. ตรวจว่า learner_profiles, learner_progress และ teacher_accounts เปิด Row Level Security แล้ว

## 2. ตั้งค่าอีเมลและลิงก์กลับ

ใน Authentication → URL Configuration:
- Site URL: https://nuttapon1052-dotcom.github.io/english-learning/
- Redirect URLs: เพิ่ม URL เดียวกันทั้งแบบมีและไม่มี slash สุดท้าย
- เพิ่ม http://localhost:5173/english-learning/ ถ้าทดสอบเครื่องตนเอง

เปิด Email provider และเปิด Confirm email
สำหรับการใช้งานจริง ให้ตั้ง Custom SMTP ใน Authentication → Email เพื่อส่งอีเมลยืนยันและรีเซ็ตรหัสผ่านแก่ผู้เรียนทั่วไป บริการอีเมลค่าเริ่มต้นของ Supabase มีโควตาและอาจส่งได้เฉพาะสมาชิกทีม

## 3. ใส่ข้อมูลสาธารณะสำหรับเชื่อมต่อ

หา Project URL และ Publishable key ใน Settings → API Keys (หรือ anon public key ในโปรเจกต์เก่า)
แก้ public/auth-config.json:

```json
{
  "supabaseUrl": "https://YOUR_PROJECT.supabase.co",
  "supabasePublicKey": "sb_publishable_..."
}
```

ค่านี้ตั้งใจให้เปิดเผยได้ การคุ้มครองข้อมูลอยู่ที่ RLS และ token ของผู้ใช้
ห้ามใส่ secret key, service_role key หรือรหัสผ่านฐานข้อมูล
push ไป main แล้ว GitHub Actions จะสร้างและเผยแพร่เว็บใหม่

อีกทางเลือก: ตั้ง Repository Variables ชื่อ VITE_SUPABASE_URL และ VITE_SUPABASE_ANON_KEY ระบบ build จะอ่านให้ ไม่ต้องแก้ JSON

## 4. เปิดหน้าครู

1. สมัครบัญชีผ่านเว็บและยืนยันอีเมลก่อน
2. ใน SQL Editor ใช้อีเมลของครูแทนค่าในคำสั่งต่อไปนี้:

```sql
insert into public.teacher_accounts(user_id)
select id from auth.users where email = 'YOUR_TEACHER_EMAIL'
on conflict do nothing;
```

3. ออกจากระบบแล้วเข้าใหม่ จะเห็นปุ่ม “ผู้เรียน” ในหน้าบัญชี
4. หน้าครูแสดงชื่อ อีเมล จำนวนบทที่จบ บทที่กำลังเรียน และเวลาซิงก์ล่าสุด จำกัด 500 บัญชีในรุ่นนี้
5. นักเรียนอ่าน/บันทึกได้เฉพาะข้อมูลของตนเอง ครูอ่านได้แต่แก้ความก้าวหน้าผู้อื่นไม่ได้ ผู้เรียนสร้างสิทธิ์ครูเองไม่ได้

## 5. ตรวจด้วยสองบัญชีก่อนเปิดรับผู้เรียน

- สมัคร A และ B ยืนยันอีเมล เข้า A เรียนหนึ่งบท แล้วออกจากระบบ
- เข้า B: ต้องไม่เห็นความก้าวหน้าของ A
- เข้า A ในอีกเบราว์เซอร์: ต้องเห็นบทที่จบและตำแหน่งที่เรียนค้าง
- เปิดแท็บ Network และลองส่ง GET learner_progress?user_id=eq.ID_OF_B ด้วย token ของ A: ต้องได้รายการว่าง
- ลอง upsert user_id ของ B ด้วย token A: ต้องถูก RLS ปฏิเสธ
- บัญชีครูเห็นทั้ง A/B; บัญชีผู้เรียนเปิด #teacher จะไม่เห็นข้อมูลผู้อื่น
- ทดสอบส่งลิงก์ลืมรหัสผ่าน เปลี่ยนรหัส และเข้าสู่ระบบด้วยรหัสใหม่
- ถ้าออฟไลน์ ข้อมูลยังเก็บในเครื่องและหน้าบัญชีบอกว่ายังไม่ซิงก์ เมื่อกลับออนไลน์จะลองซิงก์อีกครั้ง

ความก้าวหน้าจากผู้ใช้ชั่วคราวไม่ถูกนำเข้าบัญชีอัตโนมัติ ปุ่ม “นำความก้าวหน้าในเครื่องเข้าบัญชีนี้” ให้ผู้เรียนเลือกเอง ป้องกันข้อมูลคนก่อนหน้าปนบนเครื่องที่ใช้ร่วมกัน

การซิงก์รวมบทที่จบ คำศัพท์ และกิจกรรมแล้วเก็บตำแหน่งเรียนจากเวลาที่ใหม่กว่า
หากสองเครื่องแก้ข้อมูลพร้อมกันในเวลาใกล้กันมาก ให้รอให้สถานะ “ซิงก์แล้ว” ก่อนเปลี่ยนเครื่องเพื่อหลีกเลี่ยงการเขียนทับ
คะแนนทักษะเป็นตัวนับการฝึก ไม่ใช่การรับรองระดับภาษา

## เข้าสู่ระบบด้วย Google / Gmail

ทำตาม [คู่มือตั้งค่า Google](./GOOGLE_SETUP.md) เพื่อเปิดปุ่มเข้าสู่ระบบด้วย Google ไม่ต้องสร้าง Supabase API key หรือรัน SQL ใหม่

## การติดตามข้อมูลและการซิงก์รุ่นล่าสุด

ความก้าวหน้าอยู่ใน Table Editor → learner_progress คอลัมน์ state โดย user_id ตรงกับ User UID ใน Authentication → Users
สำเนาใน localStorage แยกตามบัญชี ใช้สำรองเมื่อเน็ตขาด และส่งเมื่อเชื่อมต่อได้
ร่างคำตอบและการตั้งค่ารวมอยู่ใน state; ไฟล์เสียงที่อัดไม่ถูกอัปโหลด
การอัปเดตใช้ updated_at เพื่อตรวจว่าไม่มีเครื่องอื่นเขียนก่อนหน้า ถ้าชนกันจะอ่านและรวมใหม่ ใช้ RLS/คอลัมน์เดิม ไม่ต้องรัน SQL เพิ่ม

ดู [รายงานตรวจบทเรียนและการซิงก์](../docs/LEARNING_AUDIT.md) และทดสอบบัญชีเดิมจากเบราว์เซอร์ที่ไม่มีข้อมูลเก่า
ก่อนย้ายเครื่อง รอ “ซิงก์ความก้าวหน้าแล้ว” ถ้ายังไม่ซิงก์ ให้ต่อเน็ตและกดซิงก์อีกครั้งในหน้าบัญชี
