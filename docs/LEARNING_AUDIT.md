# ตรวจเนื้อหา 24 บทและความก้าวหน้าข้ามเครื่อง

## บท 2: ทำไมเดิมไม่มี is

เดิมคำศัพท์และตัวอย่างของบทนี้จำกัดอยู่ที่ I / You / We / They จึงมี am และ are เท่านั้น
แต่ subtitle ระบุ “am / is / are” และเป้าหมายบอกว่าจะเลือก verb to be ได้ ทำให้สิ่งที่สัญญากับผู้เรียนไม่ครบ
นี่เป็นข้อผิดพลาดด้านความครบถ้วนของเนื้อหา ไม่ใช่การที่ is ใช้ไม่ได้

แก้เป็นบทประธานทั้งเจ็ด: I → am; He / She / It → is; You / We / They → are
เพิ่ม he, she, it, is ในคำศัพท์ มีตัวอย่างครบเจ็ดประธาน อธิบายชื่อเอกพจน์/พหูพจน์และ you คนเดียว และฝึก is ในการฟัง เรียงคำ และเติมคำ

## ผลตรวจรายบท

ตรวจเป้าหมาย คำศัพท์ คำแปล ตัวอย่าง หลักไวยากรณ์ โจทย์ฟัง/อ่าน เฉลย คำเรียง เติมคำ และตัวอย่างเขียน
ทุกบทมีตัวอย่างการเขียนที่เข้ากับคำเริ่มต้น เฉลยฟัง/อ่านกระจายตำแหน่ง และแบบฝึกเขียนแสดงชัดว่าไม่ได้ตัดสินไวยากรณ์อัตโนมัติ

| บท | สิ่งที่ตรวจและแก้ |
|---|---|
| 1 ทักทาย | My name is / What is your name และ Nice to meet you สอดคล้องกัน; คงเนื้อหาหลัก |
| 2 ประธานและ be | เติม is / he / she / it และคู่ประธานทั้งเจ็ด; แก้หัวข้อและแบบฝึก |
| 3 อาชีพ | เติม work/works ตามประธาน, a/an กับอาชีพเอกพจน์และการละ a/an ในพหูพจน์ และอธิบาย in/at ตามบริบท; แก้ช่องว่างก่อนจุด |
| 4 กิจวัตร | เติม present simple / -s สำหรับบุคคลที่สาม และ at/in; แก้ช่องว่างก่อนจุด |
| 5 สั่งอาหาร | อธิบายนามนับได้ a/an เทียบ rice/water และ would like to + กริยา |
| 6 ความชอบ | เติม likes / does not like / Does she like และกริยารูปเดิมหลัง do/does |
| 7 want/need/can | แยก need + คำนาม กับ need to + กริยา และ can ไม่ใช้ to/-s |
| 8 คำเชื่อม | ระบุ because ตามด้วยประโยคในโครงสร้างที่สอน |
| 9 คำถาม | เพิ่มตัวอย่าง when/who/why ให้ครบศัพท์ แยก do/does จากคำถาม verb to be และ Who ที่เป็นประธาน |
| 10 บทสนทนา | คำถาม การชวน และ but สอดคล้องกับบทก่อน; คงเนื้อหาหลัก |
| 11 ซื้อของ | เพิ่มกรณีนามนับไม่ได้/พหูพจน์ของ How much is/are |
| 12 ถามทาง | เปลี่ยนศัพท์ across เป็นวลี across from ให้ตรงกับตัวอย่าง “ตรงข้าม” |
| 13 สั่งอาหารสุภาพ | would like / I'd like / without และเฉลยสอดคล้องกัน; คงเนื้อหาหลัก |
| 14 นัดหมาย | เติม at night และวิธีระบุ a.m./p.m. เพื่อให้เวลาชัดเจน |
| 15 อากาศ | It is / should + กริยา และเฉลยสอดคล้องกัน; คงเนื้อหาหลัก |
| 16 สุขภาพ | have a headache / feel well / Could you help me ถูกตามบริบท; คงเนื้อหาฝึกภาษา |
| 17 อดีต | เติม went, was, were, did, ตัวอย่างกริยาไม่ปกติ/ปฏิเสธ และแยก Did จาก Was/Were |
| 18 อนาคต | be going to + กริยารูปเดิม ตรงกับประธานและเฉลย; คงเนื้อหาหลัก |
| 19 เปรียบเทียบ | อธิบาย than กับทั้ง -er และ more, bigger/better และการละคู่เปรียบเทียบเมื่อบริบทชัด |
| 20 โรงแรม | เพิ่ม under the name Mali ในตัวอย่างให้ตรงสิ่งที่อธิบายในไวยากรณ์ |
| 21 อีเมล | มีตัวอย่างเขียนอีเมลครบคำทักทาย ใจความ และคำลงท้าย |
| 22 ประชุม | เพิ่ม I think และประโยคนัดประชุมให้ครบเป้าหมายของบท |
| 23 โทรศัพท์ | May I / leave a message / will + กริยารูปเดิม และเฉลยสอดคล้องกัน |
| 24 ภารกิจรวม | ปรับ helpful เป็น “มีประโยชน์ / ช่วยได้” ให้ตรงกับ That was helpful |

คำอ่านไทยเป็นเพียงคำอ่านประมาณ ไม่ใช่ IPA หรือการตรวจความถูกต้องของสำเนียง
24 บทเป็นเนื้อหาพื้นฐานตามเป้าหมายที่ระบุ ไม่ใช่หลักสูตรไวยากรณ์อังกฤษทั้งหมด

## ข้อมูลอยู่ที่ไหน

- Supabase Authentication: บัญชีและตัวตนผู้ใช้
- public.learner_profiles: ชื่อและอีเมลของบัญชี
- public.learner_progress: state ของผู้เรียนหนึ่งแถวต่อ user_id พร้อม updated_at จากเซิร์ฟเวอร์
- localStorage: สำเนาความก้าวหน้าสำหรับบัญชีแต่ละคน และความก้าวหน้าแบบไม่สมัครแยกกัน

เจ้าของเปิด Supabase → Authentication → Users เพื่อหา User UID ของบัญชีตนเอง
แล้วเปิด Table Editor → learner_progress เลือก user_id เดียวกันและดูคอลัมน์ state
ผู้เรียนเข้า Gmail เดิมที่ผูกบัญชีเดียวกันในเครื่องใหม่ เว็บโหลดจากคลาวด์ก่อนรวมกับสำเนาในเครื่อง
ความก้าวหน้าแบบไม่สมัครจะไม่เข้าบัญชีเอง ให้ใช้ปุ่มนำความก้าวหน้าในเครื่องเข้าบัญชีนี้เมื่อเป็นข้อมูลของตน

## จุดบกพร่องด้านการซิงก์ที่แก้

1. ออกจากระบบขณะมีข้อมูลรอส่ง: เดิมยกเลิก timer ได้ก่อนเขียนคลาวด์; ตอนนี้รอการส่งสำเร็จ ถ้าล้มเหลวยังอยู่ในบัญชีและเก็บสำเนาเดิม
2. สองเครื่องอ่านแถวเดียวกันแล้วเขียนพร้อมกัน: เดิม upsert ตัวหลังทับตัวแรก; ตอนนี้ PATCH เฉพาะ updated_at ที่อ่านมา ถ้าเวอร์ชันเปลี่ยนจะอ่านและรวมใหม่
3. สองเครื่องสร้างแถวแรกพร้อมกัน: insert ที่ชนกันจะอ่านแถวที่มีแล้วและรวม ไม่ upsert ทับ
4. ร่างคำตอบอยู่ในหน่วยความจำ: ตอนนี้บันทึกคำตอบฟัง/อ่าน ข้อความเขียน คำเรียง คำเติม และสถานะตรวจคำตอบแยกตามบท
5. รวมรางวัลได้แต่จำนวนกิจกรรมต่ำกว่าจริง: คำนวณยอดขั้นต่ำจากชุดรางวัลที่รวมแล้ว
6. ข้อมูลเก่าทำให้สิ่งที่รีเซ็ตกลับมา: ใช้ resetAt แยกข้อมูลก่อน/หลังการรีเซ็ต
7. รายการข้อผิดพลาดจากสองเครื่อง: เก็บเวลาที่พลาด/แก้แล้ว เพื่อรวมโดยไม่ปลุกข้อที่แก้ไปแล้ว
8. การนำเข้าข้อมูลจาก guest/ไฟล์สำรอง: รวมบทและร่างคำตอบโดยใช้ resetAt ของบัญชีปลายทาง เพื่อไม่ล้างข้อมูลของบัญชีด้วยประวัติรีเซ็ตคนละชุด
9. สถานะไม่ชัดตอนเรียน: มีสถานะซิงก์บนทุกหน้าของบัญชี และเริ่มส่งแบบ keepalive เมื่อซ่อน/ออกจากหน้า

ใช้คอลัมน์และ RLS เดิม ไม่ต้องรัน SQL เพิ่ม การส่งเบื้องหลังเป็นความพยายามสำรอง ไม่รับประกันการส่งเมื่อปิดเบราว์เซอร์ทันทีหรือไม่มีอินเทอร์เน็ต
ก่อนย้ายเครื่องให้เห็น “ซิงก์ความก้าวหน้าแล้ว” ถ้า “ยังไม่ซิงก์” ข้อมูลใหม่ยังอยู่ในเครื่องต้นทาง
ไฟล์เสียงที่อัดไม่ถูกอัปโหลดตามพฤติกรรมเดิม; กิจกรรมการฝึกพูดซิงก์ได้ แต่ไฟล์เสียงไม่ตามข้ามเครื่อง

## การตรวจสอบ

- ทดสอบเนื้อหาและเฉลยที่ตรวจด้วยคนครบ 24 บท รวมคู่ประธาน/am/is/are และ bank เรียงคำ
- ทดสอบเบราว์เซอร์เปิดและทำกิจกรรมทุกบทจนจบและโหลดกลับ
- ทดสอบด้วยสองบริบทเบราว์เซอร์และ REST server จำลองที่แยกข้อมูลตามบัญชี: จบบทในเครื่องแรก ออกจากระบบพร้อมข้อมูลรอส่ง แล้วเรียนต่อในเครื่องที่ไม่มี localStorage เดิม
- ทดสอบ insert/update ที่แข่งกันผ่าน auth client จริงกับ fetch server จำลอง; reset; drafts; การรวมรางวัล; เน็ตล้มเหลวและ retry
- ตรวจ Supabase จริงแบบไม่ใช้บัญชีผู้เรียน: เชื่อมต่อ Auth, Google redirect และการปฏิเสธอ่านข้อมูลโดย anon

การทดสอบอัตโนมัติไม่ได้อ่านแถวส่วนตัวของผู้ใช้หรือเข้าสู่บัญชี Google แทนผู้ใช้
การยืนยันข้อมูลจริงของบัญชี: ทำบทหนึ่งจนขึ้นสถานะซิงก์ แล้วเข้า Gmail เดิมในหน้าต่างส่วนตัว/เครื่องอื่น ต้องเห็นบทที่จบและจุดเรียนเดิม
